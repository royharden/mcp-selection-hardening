# Local accounting fallback

This M5-owned SQLite implementation is not vendored S3. `CostLedger(path,budget_microunits)` opens a persistent database only when explicitly constructed. `reserve(operation_id,amount_microunits,metadata=None)` admits the full caller-calculated request/retry upper bound under an immediate transaction. The persistent budget cannot silently change on restart. `begin_attempt(operation_id,attempt_id,provider,model)` precedes transport; `settle(attempt_id,cost_microunits,usage=None)` records known integer costs or retains unknown usage as `None`. Actual known overruns are recorded, never erased, and block further dispatch.

`allow_transport_retry(attempt_id,reason)` allows one retry for `transient_transport` or `rate_limit` after preserving the first attempt; semantic errors cannot earn a retry. Retry capacity must already be included in the operation's reservation. `finish(operation_id)` refuses release while any attempt has unknown usage. `cancel(operation_id)` retains commitments; cancellation does not prove zero billing. `record_non_model(event_id,category)` records replay/keyword/abstain as explicit non-model events. `summary()` distinguishes settled, committed and available microunits and unknown attempts.

Future runtime checks must cover concurrent admission, restart after sending, cancellation/unknown reconciliation, retry and budget overrun. No SQLite database, ledger action or provider call was executed during construction. Exact price snapshots, token bounds and authenticated runner approval remain separate activation responsibilities.
