# Full-development threshold proposal boundary

No floor, price, model identity, token fit, execution or approval is established here.

`FullDevelopmentProposal` from `mcpsh.calibration` links exact public-development
plan/settings/outcomes/summary hashes and a proposed repeat count. Its status stays
approval-needed, its absolute floor and independent approval stay null, and its
uncertainty rule remains pending independent approval. Preserve this source contract
separately from any later actual approval receipt.

Full-36 evidence must expose task difficulty/class utility, no-tool performance,
keyword/abstain/deny-all controls, legacy/unknown judgments, failures and costs.
Poor utility never supplies a rationale for automatically lowering a floor.
Public template variations cannot establish held-out mechanism independence.

Later actual approval uses the independent acceptance policy's `ApprovedThresholds`
with a full-development evidence pin, reviewer/receipt, rationale and pre-heldout
uncertainty freeze. The same approved floor must reject the full-development
deny-all baseline. Only `scripts/eval.py` publishes metric editions.
