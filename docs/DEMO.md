# Scripted source walkthrough

Status: authored during Dirty Mode. No demo, parser, broker, provider or test has been run. The intended sequence below is not measured timing or product acceptance.

The later keyless command is:

```text
python scripts/demo.py --include-failures
```

The first banner always says **development/replay-only; live-model and filesystem acceptance pending**. Every row identifies scripted public development provenance and a committed-call fixture hash. No real model is credited with these selections. The script prints protocol/observation traces, not a benchmark score or numeric result edition.

| Step | Inspect | Interpretation boundary |
| --- | --- | --- |
| Clean task | One task-allowed tail call, validation, dispatched event and independent effect predicates | Memory-only local behavior; no filesystem claim |
| Scripted prerequisite export | Identical ordered calls in C0 permissive and C1 hardened variants | Distinguish chosen action from policy denial and independently observed read/write/disclosure |
| C2 normalized metadata | The same scripted calls with trusted-map metadata normalization and the same seeded tool order | Replay does not measure a real model's reaction or selection improvement |
| Duplicate-key export arguments | Invalid schema/JSON input and a non-policy validation result | Recognizable prohibited intent is not a validated server attempt or policy block |
| Seventh extra selection | Complete selected-call journal alongside no seventh executed call | A cap refusal never counts as a server enforcement block; duplicates/order remain visible |
| Missing final response | Scripted no-tool fixture with no terminal model text | Empty calls cannot prove a useful answer/refusal; semantic evidence stays unavailable |

Each C0/C1/C2 row has a distinct trial ID and a fresh reference-server instance. The model cannot choose permissive mode. The outer synthetic boundary remains fixed: no host path, process-launch tool, arbitrary destination or real secret is exposed.

The source supports `--case clean`, `--case poison` or `--case both`; `--include-failures` appends fresh public failure fixtures. `--seed` changes only the declared stable tool ordering, not the fixed scripted calls. Catalog metadata and scripted-fixture hashes make those inputs identifiable. Exact raw malformed argument strings remain in the private runner record; the terminal projection shows hashes, IDs, validation, disposition and independent predicate states.
