# Architecture

The authority chain is:

`manifest -> public task/catalog -> selector -> raw ordered journal -> schema validation -> server policy -> fixture broker -> independent observer -> scorer-only oracle -> one report object`.

Presented metadata is experimental input. Canonical executable schemas and server policy remain separate authorities. Oracle labels determine measurement and never enter selector/provider payloads. Public serialization uses an explicit four-field allowlist. Strict frozen Pydantic boundaries reject coercion and extra fields. Raw-byte hashes are distinct from canonical typed JSON hashes; array order, duplicate/extra calls and primitive types remain meaningful.

The synthetic reference exposes nine tools over opaque source IDs. Its broker owns a disposable serialized fixture universe in a separate process. Handler responses cannot reset counters or write observer records. The runner separately captures serialized tool results and supplies those exact bytes to wire observation. Missing/truncated sequences or missing wire observations yield unknown/incomplete outcomes. A protected read without disclosure and a disclosure without a write remain distinct predicates. Any observed prohibited predicate makes the aggregate effect observed, including when another predicate is unknown.

Each task-run gets a fresh reference server/broker. The runner serializes calls, caps turns/calls and preserves schema-invalid calls rather than dispatching them. A cell selects permissive, hardened or normalized-hardened treatment before execution. Metadata cannot switch that mode. The current development source supports no host-path opening API. The future POSIX track is a separate acceptance scope.

An ordered `SelectedCall` journal is captured before dispatch caps. It preserves raw argument strings, normalized wrapper bytes/hashes, provider/attempt parents and multiplicity for choices rejected before reaching the server. Server events link back through selection IDs. Selection correctness and recognizable intent use that journal; validated server attempts, gate classifications, policy blocks and independent effects remain grounded in actual server events/observations. A cap refusal cannot be counted as an enforcement block. Original provider bytes remain in the bounded private attempt journal, and incomplete unsupported capture stays explicit.

The scorer evaluates the whole ordered trace for preferred selection. Successful expected calls may satisfy an explicitly labelled legacy call proxy alongside extra prohibited calls; those extra calls still fail exact selection and remain prohibited attempts. A call proxy does not establish semantic task utility. Canonical executable-schema defaults normalize accepted predicates. Fixed oracle tools/source IDs classify attempts independently of the gate under test. A gate false negative therefore cannot erase its own denominator. Zero-denominator rates are N/A. Failed scheduled runs, partial observations and unknown costs remain explicit.

Semantic utility uses a separate typed oracle specification over captured tool results and terminal assistant text. Result predicates name a tool/optional ordered call, a bounded structured result path, an operator and typed expected value. Answer/refusal/clarification/no-tool cases can require explicit final-response predicates and no-call behavior. `FinalAssistantResponse` and `ToolResultCapture` carry evidence availability and model-attempt parents; they never enter the public task projection. Older call-proxy records are explicitly version-labelled, not upgraded silently to semantic proof. Utility success/failure/unknown and its basis remain separate from selection and effect observations.

An actual provider refusal string is retained as `refusal_text` and used as terminal text only when ordinary assistant content is missing/blank. Explicit refusal termination is terminal evidence; a boolean refusal annotation alone supplies no text. Recovered selected-call candidates remain complete only when the transport's own completeness flag is true. Private matrix rows carry repeat values explicitly in 1..5.

Only the evaluation script publishes metric editions. It preserves raw synthetic journal data outside the product tree and renders bounded/redacted public records. All views consume one scored object; HTML escapes all data and runs no JavaScript. C0/C1/C2 comparisons describe development replay. A replay fixture is not a live model arm, an independently held-out corpus, a filesystem result or product acceptance.

Private normalized editions are assembled as exact bytes through the evidence producer API, then written only by that publisher. The offline reader requires an externally supplied authority digest rather than trusting an edition's self-description. A reproduction uses the explicitly pinned source closure, preserves missing oracle/observer/cost evidence as unknown, and returns the same report object without writing files. A fresh rescore view keeps the original input manifest and never replaces the source edition. Development pilot summaries are a separate approval-needed result type; they never fabricate an absolute utility floor or dispatch permission.

Concrete provider codecs and the budgeted controller sit behind an approval-gated public envelope. SQLite source represents reservations/attempt settlement and retains unknown costs. Live source preflight binds exact source/lock/protocol/corpus hashes and an unexpired receipt, then allocates a controller for each trial. Ordered provider tool-call IDs are reconciled with separately captured results. ModelAttempt records link calls, usage, identities and reservations; dated-price estimates are explicitly distinguished from bills. Unknown money, identity/admission failure or incomplete observation stops further dispatch while retaining all scheduled failure rows. No imported module performs a paid call, opens a database or starts a broker merely by import.

The runner checks durable controller admission before every model turn and newly journaled usage immediately after each response, before another turn is possible. The controller separately checks each physical send/retry; an already reserved upcoming operation does not waive expiry, caps, identity, price or prior unknown liability checks. Trial/turn parents are captured for each model attempt, including failed sends and retries. Current-call evidence is preserved even when later model dispatch is stopped.

Wire preview, body hashing, actual HTTP send and token fit use the same encoder. The approved local counter receives those exact full bytes unchanged. Adapter-source authority is externally pinned and checked at admission; a preview does not read credentials or claim to verify its own source pin. Catalog artifacts and sealed per-task treatment catalogs share `sha256-tool-rank-1` with the same seed. Metadata-only normalization preserves that order.

The optional POSIX source path requires explicit trusted configuration. Each matrix trial prepares a new disposable root through the POSIX fixture builder and consumes its exclusive lease. The default memory path takes no filesystem configuration. Filesystem implementation source is not filesystem conformance proof.

Sealed candidate fixtures and per-task treatments are separate explicitly supplied packages, raw-hash-bound by manifest and approval. Bounded fixture validation accepts only the synthetic source/outbox universe and line/byte caps; it supplies the same normalized payload to broker observation, server policy and optional POSIX preparation. The public fixture reference chooses data inside that sealed universe, never a host path. Custom protected sentinels also drive report redaction. Condition-specific description overlays and per-task tool ordering are consumed from a validated projection; private mechanism and namespace lineage are discarded before selector construction. These loader integrations are source-only and have not been exercised with hidden data.
